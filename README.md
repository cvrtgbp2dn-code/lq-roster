# 云端名单库（自动构建）

这个仓库是「拉群小助手」的**云端名单库**数据源。工具每次打开会来这里比对版本号，有新版才下载。

## 平时你只需要做一件事

**更新名单库 —— 3 步：**

1. 打开本仓库，点进 **`source/`** 文件夹
2. 右上角 **Add file → Upload files**，把新的名单库文件拖进去
   （**文件名保持一致**，会自动覆盖旧的那份）
3. 拉到底点 **Commit changes**

完事。大约 30 秒后 GitHub 会自动转换并提交，同事下次打开工具就拿到新数据了。

> **不需要**碰 `roster.js` 和 `version.js` —— 它们是自动生成的。
> 也**不需要**任何密码或密钥。

## 怎么确认更新成功了

回到仓库首页，看 `version.js` 这个文件的**最后修改时间**是不是刚刚。
是的话就说明转换完成、已生效。

## 这三个文件分别是什么

| 文件 | 谁在维护 | 说明 |
|---|---|---|
| `source/*.csv` | **你** | 原始名单库。只有这一处需要你动手 |
| `tools/build_roster.py` | 一般不用动 | 转换脚本：合并 + 去重（不区分大小写） |
| `.github/workflows/build.yml` | 一般不用动 | 自动化流程，`source/` 一变就触发 |
| `roster.js` | 自动生成 | 数据本体，工具用它做「在库 / 不在库」判断 |
| `version.js` | 自动生成 | 版本指纹 + 条数 + 生成时间 |

## 几个要注意的点

- **`source/` 里可以有多个文件**，会自动合并（重复的只保留一份）。平时保持**一个**文件就行。
- **要"删掉"某些数据**：自动流程只做合并、不会删。需要真的重建时，先把 `source/` 里的旧文件删掉，再上传新的。
- **文件名**：只要是 `.csv` 或 `.txt` 都会被读到。建议每次用同一个文件名，避免仓库里堆一堆旧文件。
- **格式**：`.csv` 取**第一列**作为数据ID；`.txt` 则一行算一个 ID。UTF-8 和 GBK 都能识别。
